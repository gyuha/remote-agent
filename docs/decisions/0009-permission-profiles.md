# 권한 정책: 프로필 3개, 기본값 standard, 30분 뒤 자동 거부

| 프로필 | 자동 허용 | 텔레그램 승인 필요 |
|---|---|---|
| `readonly` | 읽기·검색 | 없음. 쓰기·셸은 차단하고 Codex 샌드박스는 read-only |
| `standard` (기본) | 읽기·검색, 작업 폴더 안의 파일 편집 | 셸 명령, 네트워크 접근, 작업 폴더 밖 접근 |
| `trusted` | 전부 | 없음. 에이전트 정의에서 명시적으로 켜야 함 |

- 에이전트 정의 파일에 허용 목록을 두어, 자주 쓰는 명령(예: `git status`, `npm test`)은 승인 없이 실행하게 한다.
- 승인 버튼: `허용` / `거부` / `이 세션 동안 같은 종류 허용`.
- 30분 동안 응답이 없으면 자동 거부하고, 거부된 결과를 CLI에 돌려주어 세션은 계속된다.

이렇게 하는 이유: 모든 호출을 승인받게 하면 쓸 수 없을 만큼 번거롭고, 전부 허용하면 원격 무승인 셸이 된다(0008).

## 기각한 대안
- `trusted`에서도 적용되는 절대 차단 목록: MVP에서는 넣지 않는다.
- 승인 있음/없음 두 단계: 읽기 전용 에이전트를 표현할 수 없다.
