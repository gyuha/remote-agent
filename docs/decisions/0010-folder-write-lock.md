# 같은 폴더 동시 실행: 폴더 단위 쓰기 잠금(턴 단위), readonly는 병렬

쓰기 권한이 있는 세션(`standard`, `trusted`)은 작업 폴더 하나에서 한 번에 한 턴(메시지 하나의 처리)만 실행한다. 나머지는 큐에서 기다리고, 대기 순서를 메신저에 표시한다. `readonly` 세션은 잠금 없이 병렬로 실행한다. 이유: CLI들은 서로의 존재를 모르므로, 같은 파일을 동시에 고치면 서로의 변경을 덮어쓴다.

## 기각한 대안
- 쓰기 세션마다 git worktree: 진짜 병렬이 가능하지만 브랜치, 병합, 정리 부담이 MVP에 비해 크고, git이 아닌 폴더에는 쓸 수 없다. 2차 후보로 둔다.
- 잠금 없음: 충돌을 감수해야 한다.

## 결과
오케스트레이터가 같은 폴더에서 구현 에이전트 여러 개를 동시에 돌려도 쓰기 작업은 차례로 실행된다.
