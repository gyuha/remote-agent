# 오케스트레이터는 MCP 도구를 받은 에이전트다. MVP에 최소 기능을 포함한다

오케스트레이터는 별도 엔진이 아니라 에이전트 하나다. 서버가 제공하는 MCP 서버(0008의 `--permission-prompt-tool`과 같은 서버)에 오케스트레이션 도구를 추가한다.
- `list_agents`: 같은 작업 폴더의 에이전트 목록을 돌려준다.
- `send_to_agent(name, message)`: 하위 에이전트의 세션에 메시지를 보내고, 끝날 때까지 기다려 결과를 돌려준다(동기).

하위 에이전트 호출도 일반 세션과 같은 경로를 탄다. 자기 토픽에 출력이 보이고, 권한 프로필(0009)과 쓰기 잠금(0010)이 그대로 적용된다. 호출 대상은 같은 작업 폴더의 에이전트로 제한한다.

## 기각한 대안
- 서버 코드의 선언형 워크플로(계획 → 구현 → 리뷰): 예측은 가능하지만 "에이전트가 에이전트를 관리"하는 요구에 맞지 않는다.

## 결과
- Claude Code 자체 서브에이전트와 겹친다. 우리 오케스트레이터의 존재 이유는 다른 CLI를 섞는 것과 하위 작업을 메신저에서 보고 승인하는 것이다.
- 데드락 방지(2026-11-09 결정): 쓰기 잠금(0010)의 주인은 세션이 아니라 최초 턴에서 시작된 **호출 체인**이다. `send_to_agent`로 호출된 하위 턴은 같은 잠금을 물려받는다. `send_to_agent`가 동기 호출이라, 호출한 쪽이 기다리는 동안에는 도구를 실행하지 않으므로 동시에 쓰는 주체는 여전히 하나다. 대가: 관계없는 다른 세션은 체인 전체가 끝날 때까지 기다린다.
