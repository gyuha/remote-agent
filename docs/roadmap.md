# 로드맵 — MVP 이후 검토 항목

MVP 결정(`decisions/0001`~`0014`)을 내릴 때 일부러 미뤄 둔 것과, 아직 질문으로 만들 만큼 구체화되지 않은 것을 모았다. MVP를 만든 뒤 새 의제를 열 때 여기서 시작한다.

## 2차 후보 (결정 때 미룬 것)
- 메신저: 디스코드, 슬랙. "스레드 = 세션"으로 옮긴다(0004, 0007)
- CLI: OpenCode(`opencode serve`), Antigravity(`agy`. 권한이 막혀도 exit 0으로 끝나므로 별도 처리 필요)(0004)
- 리눅스에서 `agy`·OpenCode 헤드리스 로그인 확인(0003)
- 세션별 git worktree를 이용한 병렬 쓰기(0010)
- `trusted`에서도 적용되는 절대 차단 목록(0009)

## 1단계 구현 뒤 남은 작업 (2026-11-09 루프에서 나온 것)
- 보안: `allow_session`이 명령의 첫 단어로 매칭되어, `npm …`을 세션 동안 허용하면 `npm test && rm -rf /`도 자동 허용됨. 제어 문자가 들어간 명령에는 세션 허용을 적용하지 않도록 계약 변경 필요 (사용자 결정)
- [낮음] Claude Code 자체의 MCP 도구 호출 시간 제한이 30분 승인 대기보다 짧을 수 있음. 실제 바이너리로 확인 (`MCP_TOOL_TIMEOUT` 후보)
- 0010의 "대기 순서를 메신저에 표시" 미구현
- 텔레그램 429 `retry_after` 재시도, 승인 뒤 키보드 제거 미구현
- `appendEvent` 이벤트 기록 미구현 (웹 UI 로그 보기의 전제, 0013)
- 같은 대상에게 처음 위임하는 호출이 동시에 오면 토픽이 중복 생성될 수 있음. Codex 오케스트레이터는 위임 불가(MCP 도구 없음)
- 실제 텔레그램 봇과 실제 `claude`/`codex`로 하는 수동 E2E 검증 (루프에서는 외부 통신 금지로 가짜만 사용)
- 2단계: 웹 UI(0012·0013), launchd/systemd 설치(0003), 로그인 점검(0014)

## 아직 흐릿한 주제
- 예약 실행(cron)·주기 작업: cokacdir와 Hermes 모두 있지만, 이 시스템에 필요한지 아직 모른다
- 오케스트레이션 2단계: 비동기 위임, 병렬 팬아웃, 하위 에이전트 간 공유 컨텍스트. MVP의 동기 호출(0011)을 써 본 뒤에 질문이 된다
- 장기 메모리·스킬 축적: 각 CLI 자체 기능(CLAUDE.md, AGENTS.md)에 맡길지
- 사용량·비용 추적과 구독 한도 대응
- 여러 머신(노드)에 걸친 실행
